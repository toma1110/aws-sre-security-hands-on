# シナリオ：shop-api のエラー増加

以下はNorthstar Retailという架空の小売サービスを使った机上演習です。会社名、サービス名、時刻、担当、イベント、記録はすべて架空です。実在のAWS環境や顧客情報は含みません。

## サービスと担当

| 対象 | このケースで分かっていること | 確認担当の例 |
|---|---|---|
| `shop-api` | 利用者向けAPI。5xxエラーが増加 | アプリ担当 |
| `orders-db` | `shop-api` が注文処理で利用。応答遅延が見つかった | DB担当 |
| リリース展開 | アラートの18分前に開始。リクエスト解析の変更を含む | リリース担当／アプリ担当 |
| role session | 通常と異なる記録をセキュリティ担当が見つけた。principalと送信元は未照合 | セキュリティ担当 |

| 演習上の役割 | 担当すること |
|---|---|
| SRE当番 | 初動の調整と時系列の記録 |
| アプリ担当 | `shop-api` とリリースの確認 |
| DB担当 | `orders-db` の確認 |
| セキュリティ担当 | role sessionの記録を調査 |
| サービス責任者 | 本番変更を判断・承認する役割の例 |

一人で行うときは、各役割の視点を順に書き出します。この役割分担は演習用の例です。実際の組織の担当者や承認権限を示すものではありません。

## 開始時点

時刻はすべて架空のJSTです。

- 10:00、`shop-api` の5xxエラー増加を知らせるアラートが届きました。
- 10:00時点で `orders-db` の応答遅延も報告されています。遅延が始まった時刻と両者の因果は分かりません。
- アラートの18分前にリリース展開が始まり、リクエスト解析が変更されました。rollbackの判断はまだありません。
- Pagerには「不正アクセスの可能性」とあります。攻撃者、侵害、情報漏えいは確認されていません。

## 追加情報

セキュリティ担当は通常と異なるrole sessionの記録を見つけました。記録を見つけた時刻、principal、送信元、セッションが開始された時刻はまだ照合できていません。これは調査の手掛かりであり、不正な利用や侵害の確定ではありません。

## 先に読める証跡の候補

次の4点は、架空ケースで参照できる読み取り専用資料です。最初に確認する3点を選び、確認したい問いと担当を決めます。残る1点も後続の確認候補として残します。

1. `shop-api` の時刻付き5xxエラー指標
2. リリース記録とリクエスト解析の変更差分
3. `orders-db` の時刻付き遅延指標
4. role sessionに関する時刻付き監査記録

演習ではこれらの実データを提供していません。資料を読む前に答えを作らず、「何が分かるか」「誰がいつ確認するか」を決めてください。実際に確認したような結果を作り足さないでください。

## 決めること

- 何を事実、仮説、未確認として残すか
- 影響を特定できたか、まだ不明か
- 展開を一時停止するか、適用済み変更を戻すか、調査を続けるか。必要なら組み合わせる
- 判断者、承認、利用者影響、変更を戻す条件
- 次の連絡を誰がいつ行うか

展開停止は新たな展開を進めない判断です。rollbackは既に適用した状態を戻す別の変更です。どちらも自動的に安全または正解とは限りません。互換性、操作権限、利用者影響、確認方法が分からない場合は未確認として判断者へ渡します。
